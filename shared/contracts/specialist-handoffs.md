# Specialist Handoff Contract v1

Use `lumiverse-toolkit.specialist-handoff/v1` for project-linked work delegated by Project Steward. Isolated specialist tasks do not require a project handoff.

The validated packet contains:

- stable `task_id`, optional `project_id`, exact `specialist`, and `operation`;
- target artifact stable ID/type/status;
- ordered source authority, documentation snapshot, relevant canon subset, and available source files;
- agency, token/mobile, compatibility, and preservation constraints;
- confirmed dependencies only;
- project/artifact-scoped policies;
- specialist-specific requirements;
- fields and unknown data that must survive;
- the required return contract.

Required specialist return items:

1. `completed_artifact` — or an explicit blocker when completion is impossible;
2. `artifact_passport`;
3. `validation_findings`;
4. `proposed_record_changes` for canon, entities, dependencies, policies, or artifact status;
5. `unresolved_questions`.

Validate packet structures with `shared/validators/specialist_handoff.py`.

## Lorebook Forge

Use specialist `forge-lumiverse-lorebooks`.

Supply:

- creative-authority mode;
- canon subset and ownership boundaries;
- requested Character, Persona, or Global scope;
- target documentation snapshot;
- token-budget preference;
- representative positive, negative, and collision snippets;
- native World Book export template when full-fidelity serialization is required and available.

The specialist owns entry architecture, keyword/selective logic, position/depth/role, order/priority, timing, groups, recursion, vectorization, deterministic validation, activation simulation, export mode, and Lumiverse live-test guidance.

Do not reinterpret tier as prompt position, force constants/recursion, or claim native-schema fidelity without a current native template.

## Preset Converter

Use specialist `lumiverse-preset-converter` only for SillyTavern Chat Completion → Lumiverse conversion/audit/repair.

Supply when available:

- source preset and Regex, hashes, creator notes, source and target provider/model;
- current native Lumiverse envelope from the target build;
- representative character and Dry Run output;
- project agency and preservation constraints;
- selected tracker or explicit `unselected` state;
- artifact-scoped naming/version/Regex policy.

The specialist owns effective `prompt_order`, block behavior graph, markers, roles, placement/depth, generation routes, utility behavior, variable lifetime, RNG stability, reasoning boundaries, Regex planes/targets, samplers/completion, dependencies, static validators, and Dry Run/runtime certification.

Generic roleplay presets remain tracker-agnostic. Real Frank naming, `+0.1` releases, bundled linked Regex, and current-settings preservation apply only to matching Real Frank artifacts. No starting version may be invented.

Parity precedes native enhancement. Missing Dry Run evidence means runtime certification remains pending.
