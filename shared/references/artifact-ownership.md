# Artifact Ownership

Give each fact one canonical owner. Other artifacts may reference or summarize
it only when runtime behavior requires that duplication.

| Owner | Canonical material |
|---|---|
| Character card | Stable identity, voice, core behavior, core appearance |
| Scenario | Starting conditions, immediate pressure, opening timeframe |
| World Book | Conditional world facts, secondary entities, institutions, rules, expandable history |
| Persona | User-selected identity material; never inferred player choices |
| Loom preset | Model/runtime behavior shared across compatible chats, only when separately requested |
| Project record | Stable IDs, provenance, decisions, dependencies, change and validation ledgers |

Field placement is functional. Description carries enduring facts; Personality
carries behavioral core; Scenario carries current context; examples demonstrate
voice and behavior; System Prompt or Post-History Instructions contain only
necessary runtime steering. Do not paste the same biography into every surface.

Before revision, calculate ripple effects through stable IDs, aliases,
attachments, keywords, relationships, scenarios, greetings, visual briefs, and
optional runtime consumers. Preserve untouched fields and unknown data.
