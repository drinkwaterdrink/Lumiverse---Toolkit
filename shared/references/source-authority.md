# Source Authority and Native Discipline

Use the most relevant evidence, not a single global ranking that confuses story
canon with platform behavior.

## Creative and canon authority

1. The user's current explicit instructions.
2. User-approved project canon and source-locked material.
3. Supplied official sources for a known setting.
4. Supplied secondary sources, with conflicts retained.
5. Clearly labeled inference and provisional adaptation choices.

Statuses are `USER_CANON`, `CANON`, `PROVISIONAL`, `INFERRED`, `CONFLICTED`,
and `ADAPTATION_CHOICE`. Never silently promote an inference.

## Lumiverse technical authority

1. Current observed Lumiverse behavior and captured diagnostics.
2. Current official or user-supplied Lumiverse documentation.
3. A contemporary native export from the target Lumiverse build.
4. Versioned developer documentation where implementation details matter.
5. Clearly labeled inference.

SillyTavern and other projects are compatibility sources or inspiration only.
Do not copy their names, defaults, schemas, prompt order, or macro syntax into a
Lumiverse artifact. When a useful foreign concept has no documented equivalent,
say so and keep it conceptual.

For source ingestion, inventory sources, facts, entities, dates, spoilers, and
conflicts before authoring. A timeline-specific adaptation excludes future
knowledge. Separate public facts, character knowledge, beliefs, rumors, and
hidden truth.
