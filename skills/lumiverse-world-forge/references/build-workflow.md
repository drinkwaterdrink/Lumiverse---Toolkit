# Build workflow

Guided mode uses a compact blueprint checkpoint. Fast mode accepts the supplied
brief and asks only about decisions that change the output. Full-detail mode
expands every requested entity while still using stable-ID batches.

The build stages are intake, canon inventory, blueprint, specialist authoring,
compile/package, and evidence handoff. Large builds save completed stable IDs so
they can resume without regenerating accepted entries.

Classify the world as ARC, SANDBOX, or HYBRID. Arc builds track phase changes,
entry and exit conditions, and reveals without preselecting user decisions.
Sandbox builds track standing pressures, schedules, renewable hooks, and what
continues offscreen if the user does nothing.

Create then refine is the default. Use the Idea Lab or interview route only when
requested or when a missing choice changes architecture, canon, or safety.
Maintain a build ledger for multi-stage work and require specialist capability
receipts before downstream compilation.

A connected package **must not require a dedicated Loom preset**. Preset creation
is a separate project; record recommendations and dependencies without silently
creating or embedding an undocumented preset.
